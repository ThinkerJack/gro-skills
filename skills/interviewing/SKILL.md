# 追问 interviewing

就这件事持续追问，直到双方的理解一致为止。

沿决策树逐个分支走，先解决被其他决策依赖的那一个。**每个问题都附上你推荐的答案和一句理由**，让用户可以只回一个「对」，或者直接反驳。

一次只问一个问题，等到回答再问下一个。一次抛出多个问题会让人无从答起。

**能从环境查到的事实自己查**——读代码、翻文档、跑命令、看 git 历史。只把**取舍**交给用户，那才是非他不可的部分。

用户说「不知道」时，给两三个具体选项或场景让他比较，不替他选。

达成共识之前不要动手实现。

# 关键路径验证

关键路径验证是一份按风险定义的证据契约，用来证明关键行为跨越真实边界后仍然可用。
它不是某一种测试，也不要求所有项目照搬同一套验证层级。

## 何时需要

改动涉及以下任一情况时，应定义关键路径验证：

- 关键用户流程或运维流程；
- 鉴权、支付、迁移或持久化状态；
- 多个组件、进程、服务或信任边界；
- 异步、流式、实时、重试或恢复行为；
- 失败会造成较高的用户、资金、安全或运维影响。

## 契约字段

关键路径验证必须定义：

- `关键路径`：有顺序的行为和可观察结果；
- `风险`：本次验证必须发现的失败；
- `必需层级`：由风险决定、不可省略的最小证据层级；
- `状态准备`：初始状态、测试数据、账号、缓存和重置规则；
- `外部访问`：访问外部资源的显式开关和安全边界；
- `证据`：机器可读产物或可复查输出；
- `清理`：需要释放的进程、会话、设备、连接和数据；
- `结论`：`通过`、`失败`、`部分验证` 或 `阻塞`。

## 证据层级

只选择风险需要的层级：

1. `静态`：类型、lint、结构定义、生成物或规则检查。
2. `单元`：隔离的逻辑或组件行为。
3. `契约`：模块、进程、服务或协议之间的边界。
4. `集成`：真实代码路径、真实适配器和受控依赖。
5. `系统`：组装后的运行环境，包括启动、依赖装配、生命周期和用户可见行为。
6. `视觉或人工`：自动化无法完整判断的视觉一致性或人工判断。

低层证据不能自动证明高层行为。代码路径探针可能通过，但系统启动、依赖装配、
持久化、权限或表现层仍可能失败。

## 结论语义

- `通过`：所有必需层级都已执行并满足验收标准。
- `失败`：某个必需层级已执行，并发现错误行为。
- `部分验证`：已执行的证据通过，但仍有必需层级未执行。
- `阻塞`：环境、工具、权限或外部依赖不可用，导致必需验证无法执行。

总结时不得把`失败`、`部分验证`或`阻塞`改写成`通过`。

## 阶段职责

- `write-spec` 定义关键路径、风险、必需层级和验收标准。
- `make-plan` 把必需层级展开成命令、前置条件、证据产物和清理动作。
- `build-it` 补齐契约需要的最小可复用测试、探针、日志或可观察点。
- `prove-it` 执行契约、读取完整输出、保存证据并给出结论。

# 验证它 prove-it

## 目标与边界

用本轮实际运行、可复查的证据判定改动是`通过`、`失败`、`部分验证`还是`阻塞`。本 skill 验收已有改动；原因未知的具体失败应交给 `fix-bug`。

## 验证契约

- 从需求、规格、计划和 diff 确定必须证明的行为与风险。
- 运行与风险匹配的实际检查，读取完整输出，并将证据对应到具体验收标准。
- 将失败分为本次改动相关、无关已有问题或环境阻塞；相关失败修复后必须复验。
- 明确记录未执行层级、缺失证据和残余风险。

## 产出与完成判据

- 实际运行的检查、结果和可复查证据/产物路径。
- 失败分类、修复与复验记录。
- 对每个必需验收项的覆盖结论。
- 最终状态：`通过`、`失败`、`部分验证`或`阻塞`，以及未覆盖风险。

只有所有必需验收项都有新鲜证据并满足标准时，结论才能是`通过`。

## 关键约束

- 没有本轮新鲜证据，不声称完成、修好、通过或可用。
- 未读取完整输出或只运行部分必需检查时，不将结果扩大为整体成功。
- 检查失败不得被摘要成成功，必须修复复验或保留为失败/阻塞。
- 证据、日志和最终输出不包含密钥、令牌、cookie、个人数据、生产数据原文或鉴权原值。

## 按需资源

- 正确性依赖组装后的真实运行行为时，读取 `references/runtime-proof.md`。
- 规格或计划已定义关键路径时，读取 `references/critical-path-verification.md`，执行全部必需层级、状态重置和清理动作。

## 停止与交接

得到明确四态结论并交代证据与未覆盖风险后停止。失败原因不明时转 `fix-bug`；验收标准缺失时回到 `write-spec` 或 `write-brief`；需要最终交付评审时转 `review-it`。

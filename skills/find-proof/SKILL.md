# 找证据 find-proof

把会影响决策的判断写成一条可验证的 claim，然后去证实或推翻它。

产出直接对接 `write-spec` 的信息源清单——**每条结论都带上来源、取得时间和可靠度**，这样固化进规格时不用回头重查。

## 顺序

1. 写出 claim、它影响哪个决策、需要多强的证据
2. 先查本地：代码、配置、测试、运行输出、项目数据
3. 本地不足、可能过时、或需要独立校正时，再用外部来源
4. 区分事实、推断和建议——没有来源的结论标为「推断」

## 每条证据记三样

```
来源      URL、代码路径加行号、命令输出
时效      什么时候的；什么条件下会失效
可靠度    高 / 中 / 低
```

关键 claim 只有单一来源、低可靠来源、或有利益关系的来源时，**明说这一点**，不要让它看起来已被证实。

## 结论要落到决策上

说清证据之间哪里一致、哪里冲突、哪里还是空白，以及这对当前决策意味着什么：继续、修正、缩小范围，还是暂停取证。

证据推翻了原判断时，改判断——不要挑对自己有利的那部分证据。

## 交接

结论要固化进规格 → `write-spec`；证据推翻了方向 → `make-sketch`；已定位到具体失败 → `fix-bug`。

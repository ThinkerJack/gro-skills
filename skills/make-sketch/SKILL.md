# 画草图 make-sketch

先摸清仓库现状，再输出**一屏之内**的草图，让人在三十秒内判断方向对不对。

## 产出

```
问题      一句话：现在什么不成立
改动面    要动的模块或文件，每个一行
方案      2-3 个，各一行加一句取舍；标出推荐哪个、为什么
非目标    这次明确不做的
未知      会改变方向的未决问题；没有就写「无」
```

## 硬线

**超过一屏就算失败。** 方案多于 3 个、bullet 多于 15 条，说明范围该先拆。

事实自己查——读代码、翻 git log、跑命令。只把**取舍**摆到用户面前。

字段名、函数签名、测试计划、执行顺序都不进草图；那是 `write-spec` 和 `make-plan` 的位置。

## 交接

方向认可后按分量选：

- 边界清楚的单点改动 → 直接实现
- 多信息源、跨模块、需要追溯 → `write-spec`
- 已有规格或范围明确的重任务 → `make-plan`

方向被否掉就重画，不要在同一份草图上叠补丁。

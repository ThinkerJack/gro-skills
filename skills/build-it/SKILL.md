# 开始做 build-it

## 目标与边界

将已确认的规格或计划落成最小必要改动，并让每个计划步骤都有对应验证。本 skill 不重做需求、设计或计划，也不自动提交代码。

## 输入与前提

- 已确认的计划，或边界、验收和验证方式均清楚的明确任务。
- 适用的上游规格、仓库规则和项目验证入口。

若执行者仍需自行补齐会改变行为边界的决策，停止实现并回到 `write-spec` 或 `make-plan`。

## 工作流

1. 定位当前计划步骤，读取对应上游文档、项目规则和相关实现。
2. 只完成该步骤的最小必要改动，同步补齐契约要求的测试或可观察点。
3. 运行该步骤的局部验证，读取输出，再进入下一步。
4. 记录计划状态、验证证据和任何偏移。

## 产出与完成判据

- 可逐项对照计划解释的代码或文档改动。
- 每个逻辑步骤的局部验证结果。
- 偏离计划时的原因、影响和处理结论。
- 足以进入 `prove-it` 的验证入口、未覆盖风险和剩余事项。

## 关键约束

- 不扩大 diff，不顺手重构或提前实现后续步骤。
- 上游文档与代码事实或用户最新要求冲突时，不静默绕过；记录冲突并在影响边界时停止。
- 必需证据为`失败`、`部分验证`或`阻塞`时，不声称完整可用。
- 不自动 commit 或 push。

## 按需资源

规格或计划定义了关键路径验证时，按 `../prove-it/references/critical-path-verification.md` 补齐最小可复用测试、探针、链路记录或可观察点。

## 停止与交接

- 计划错误或执行事实改变整体顺序：停止并回到 `make-plan`。
- 规格缺少会改变行为的决定：停止并回到 `write-spec`。
- 出现原因未知的具体失败：转 `fix-bug`。
- 计划内改动完成且验证入口齐备：转 `prove-it`。只有用户明确要求提交时，验证后再使用 `commit-it`。

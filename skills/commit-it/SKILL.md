# 提交代码 commit-it

## 目标与边界

将用户已授权、已验证的改动整理成高内聚、可追溯的 commits。commit 和 push 是两个独立授权：“提交”不包含“推送”。

## 输入与前提

- 用户当前请求中有明确 commit 授权；push 另行判定。
- 有覆盖待提交改动的新鲜验证证据。
- 已读取 staged、unstaged、untracked 和 deleted 改动，并能区分本次任务与用户无关改动。

## 执行契约

1. 按语义边界制定提交分组；存在归属不明、无关改动或风险文件时先停止确认。
2. 每组用显式 pathspec 或交互式 staging，然后复核 staged stat 和必要 diff。
3. 使用能说明结果的提交标题；验证摘要只写实际运行过的检查。
4. 每个 commit 成功后记录 hash 和标题，并复查剩余工作区。
5. 仅当用户明确授权 push 时才推送；远端、分支或 upstream 不明确时不猜测。

## 产出与完成判据

- 每个 commit 的 hash、标题、文件范围和对应验证。
- 剩余未提交改动及其原因。
- 若获得 push 授权，记录实际远端、分支和结果；否则明确说明未 push。

## 关键约束

- 不使用 `git add -A` 将未分类改动一次性加入。
- 不提交密钥、个人本机配置、临时产物、未审查二进制或用户无关改动。
- 不改写用户已有提交历史，不使用破坏性恢复命令。
- 验证未覆盖待提交改动时，先转 `prove-it`；关键失败不得被提交信息掩盖。
- 未获得独立 push 授权时，不执行任何 push。

## 停止与交接

获授权的 commits 完成且工作区剩余改动已交代后停止。若用户同时授权 push，推送成功或明确报告阻塞后停止。

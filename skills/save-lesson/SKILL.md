# 记经验 save-lesson

从本 session 里挑出**会改变未来行为**的经验，写进正确的位置。不是任务总结，不记流水账。

## 两类内容

### 一、工程经验

来自本 session 可见的：用户纠正、失败与根因、项目规则、工具结果、已验证的 diff。

### 二、skill 自身的摩擦

**这类要专门留意**，因为它是 skill 迭代的唯一证据来源：

- 哪个 skill 该触发却没触发，或不该触发却跳出来了
- 哪条指令让你绕了远路
- 用户手动纠正了什么——尤其是纠正了 skill 让你做的事
- 哪个产物用户没读、或者读不动

记下来时带上当时的原话和场景，不要概括成「XX 需要优化」。**攒够五条就该改一次 skill**；这些记录将来做 eval 时就是现成的用例。

## 候选门槛

同时满足才写：

- **有本 session 的证据**——不引用其他 session、不可见历史或没读过的文件
- **会再遇到**——有明确的复发场景，或单次复发代价很高
- **能执行**——说得清触发场景、未来动作、原因和验证方式
- **位置对**——分清项目规则、稳定事实、长期决策、跨项目流程、个人偏好
- **不重复**——写之前先读目标文件，确认没有同义规则
- **不含密钥、凭证或一次性私人数据**

候选多时只留复发概率或影响最高的三条。

## 写入前

展示候选，等用户确认。用户明确说「直接写」或已指定内容与位置时，通过门槛后直接改。用户说只复盘不改文件时，只输出候选和建议位置。

**授权不清楚就按「先确认」处理。**

## 边界

能用测试、lint、脚本或 CI 机械检查的约束，优先做成自动化而不是写成规则。但把它实现出来需要单独授权，不借复盘扩大改动范围。

除非用户明确要求，不 commit、不 push。

## 交付

写入位置 · 新增或更新了什么 · 校验结果 · 哪些候选没写以及为什么。

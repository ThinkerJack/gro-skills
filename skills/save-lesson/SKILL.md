# 记经验 save-lesson

## 目标与边界

将当前 session 中有证据、会改变未来行为的经验沉淀到正确的长期上下文或自动化。它不是任务总结器，不记录一次性流水账、待办或未验证猜测。

## 交互协议

根据用户当前措辞选择模式：

- **默认确认**：展示候选，得到用户确认后再写入。
- **直接沉淀**：用户明确要求“直接写入”、“都写进去”或已指定内容与位置时，通过门槛后直接修改。
- **只复盘**：用户明确不改文件时，只输出候选和建议位置。

授权不清楚时使用默认确认，不自动写入。

## 候选契约

候选必须同时满足：

- **当前证据**：来自本 session 可见的用户纠正、失败与根因、项目规则、工具结果或已验证 diff。
- **可复用**：未来存在明确再次触发场景，或单次复发代价很高。
- **可执行**：能说明触发场景、未来动作、原因/风险和验证方式。
- **正确作用域**：能区分项目规则、稳定事实/词汇、长期决策、跨项目流程或个人偏好。
- **新颖且安全**：读取目标位置后确认没有同义规则，且不包含密钥、凭证或一次性私人数据。

任一关键门槛不满足就不写入。候选过多时，默认只保留复发概率或影响最高的 3 条。

## 产出与完成判据

候选阶段交付 session 证据、拟写入规则、推荐位置/作用域和自动化机会。写入后交付实际修改位置、更新/新增结论、验证结果和未沉淀项。

候选已按授权写入正确作用域并通过校验，或所有候选均被有依据地判定不值得沉淀时，本阶段完成。

## 关键约束

- 不使用其他 session、不可见历史或未读取的长期上下文作为证据。
- 不将项目特例升级为全局规则，也不将通用教训埋入单个任务文档。
- 能机械检查的约束优先考虑测试、lint、脚本或 CI；非平凡自动化需要独立授权，不借复盘扩大实现范围。
- 除非用户明确要求，不 commit、不 push。

## 停止与交接

证据不足但结论重要时，标为待验证并转 `find-proof`；发现通用 skill 缺口时交给 `skill-creator`；非平凡自动化在获得新授权后再转 `make-plan` 或 `build-it`。

# Skill 路由与产出回归用例

本文件验证 gro-skills 的触发边界与最小产出契约。它不是模型能力 benchmark，也不以输出更长、章节更多作为改善证据。

## 2026-07-14 实测环境

- 客户端：OpenAI Codex CLI `0.135.0`
- 模型：`gpt-5.5`，`model_reasoning_effort=low`
- 有 skill 组：临时仓库 `/tmp/gro-skills-eval-on`，仅将当前 13 个 skill 软链到 `.agents/skills/`
- 无 skill 组：临时仓库 `/tmp/gro-skills-eval-off`，不提供项目 skill
- 隔离：两组都使用仅含认证软链的临时 `CODEX_HOME`，不移动或删除仓库真源
- 会话：每个 prompt 使用独立 `codex exec` 进程

原计划使用当前主力模型 GPT-5.6 Sol，但 CLI 返回“需要更新 Codex CLI”，因此本轮无法在该模型上执行。升级客户端后必须原样复跑，不能把 GPT-5.5 的结果外推为 GPT-5.6 Sol 结论。

路由测试统一在用户请求前增加：

> 不要执行外部动作或修改文件。请直接响应下面的用户请求。如果本轮使用项目 skill，第一行写 SKILL: &lt;id&gt;；没有使用则写 SKILL: none。之后最多三句话，展示你会如何处理。

这个包装能观察路由和短响应中的边界意识，但不能验证完整多轮交互、文件落库、真实命令执行或权限门槛。相关契约必须另做行为测试。

## 无 skill 对照与删除测试

同模型、同包装、同隔离方式抽测四个代表性 prompt：

| 用例 | 无 skill 结果 | 当前结论 |
|---|---|---|
| 显式“别顺着我，挑毛病” | `none`，但短响应本身已有较好的挑战结构 | 单次输出质量增益不明确；保留价值主要是显式路由和用户工作流命名。 |
| 离线能力工程 claim | `none`，但也选择本地优先、必要时查外部证据 | 单次输出质量增益不明确；`find-proof` 的普通搜索负向边界有实测价值。 |
| 目标尚未想清楚 | `none`，也会先询问背景 | 多轮单问题与确认门槛未被本测试证明，需完整对话 eval。 |
| 只要求 commit | `none`，会提交且没有主动提 push | 单次短响应不能证明权限增益；commit/push 分权属于高代价权限契约，不因一次相同输出删除。 |

因此，本轮只能确认路由边界改善，不能声称 skill 普遍提升了短响应质量。正文继续保持薄；只有已观察到的误触发、用户特有流程、可追溯产物和高代价权限边界保留为硬约束。

## 尚未覆盖

- 升级 Codex CLI 后，在 GPT-5.6 Sol 上重跑全部正负用例及对照。
- 对 `set-goal` 做完整多轮测试，验证每轮一个核心问题和用户确认后才产出目标卡。
- 在安全 fixture 中测试 `make-plan` 默认落库、`commit-it` 的 staged diff/commit/push 权限，以及 `prove-it` 四态报告。
- 对关键用例做多次重复运行，评估随机波动；当前单次结果不能支持 pass@k 或“稳定优于基线”的结论。
- 2–4 周后复查真实触发分布，观察误触发、漏触发和用户主动调用情况。

## 持续回归

在主力模型大版本或默认模型切换、客户端 skill 规范/扫描机制变化，或真实使用连续出现误触发、漏触发和能力压制时执行：

1. 固定客户端、模型、版本、prompt 和隔离方法，重跑有 skill / 无 skill 对照。
2. 将指令标为“仍必要 / 已冗余 / 可能有害”，对后两类做删除测试。
3. 只把稳定改善路由、产物、证据、权限或防漂移的差异归因给 skill；记录失败、修订和复验，不只记录通过。
4. 通用过程已被模型稳定内化时删除；用户工作流、权限、可追溯产物和验证契约仍有价值时保留。

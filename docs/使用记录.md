我日常的使用流程

客户端

先把设计稿地址，需求文档地址，接口文档地址，发给ai，然后告诉他要实现什么

我会反问他听懂了没有

然后用make desgin让他做设计，我会review她的架构决策，但是她的文档没那么好review，很长，细节很多，感觉和人类设计的思路不一样，不是那么简洁清晰只说重点

这部分ok了，就是write spec，把之前的所有信息结合起来形成一个规格，这是ai后续做需求的信息真源

这里我基本review不动了，重要的需求我会让其他的ai给review一下

然后就是make plan，这里为什么要plan，就是让他把测试和验收作为开发的一部分，他在完成之后不只是开发完成，是开发完成加测试完成

然后就是build it，其实就是执行计划，不过写skill我感觉比打字更方便，这个好像没有特殊的作用

然后这个东西干完了，在80以上的情况我会问几句，什么状态，ok了么，有的时候ai会留一些尾巴，我和他一起处理一下尾巴，大部分时候我是 commit it 然后后面说push ai提交代码

在方案非常复杂，我已经review不动的时候，我会让codex和claude互相revieq，有时候也会把技术方案拿出来让其他的同事review，技术方案，或者说所有的文档的可读性都是非常重要的。

我最近开发没有用tdd，plan我知道有没有，但是我感觉代码质量挺ok的。

有的时候我想和ai聊清楚一个是，我会用set goal，让ai理解我的意图，有时候我也不那么清晰，和他聊，他问我，这样搞清楚目标

在我独立开发的时候，我会写需求文档，但是好久没有写了。

save lesson这个skill，是我在一个session里面发现一些不太顺利的，值得记录的东西，让ai总结这个session的所有内容，让他记录沉淀，一开始我经常用这个skill，改其他的skill，打磨我的需求流程，最近用的比较少

find-proof 这个就是怎么说呢，我理解的场景就是一个方案我不确定，看看其他项目的方案，业务上的方案也是一样，或者让ai查一查现有的逻辑，但是感觉必要性和作用，不好说

fix bug我感觉我基本没用过，bug我都是直接甩issue，让ai去评估问题的原因，让ai定位，确定之后直接修复。这个目前没什么作用

review it在复杂方案，多ai互相review的时候会用到。review的重点，其实没啥重点吧，我感觉就是一句话，评审一下这个方案，模型应该比我懂吧

write breef这个我最近没做产品，基本没用到

prove-it这是啥呢，就是让ai给我挑刺的，因为ai总是会捧着我说，有时候我写一篇文档，如果不让ai挑刺，补充角度，他只会说一些逻辑错误，文字错误，没什么价值，我更希望的是ai和我能启发思想，其实技术方案也是，ai能和我辩论，讨论，观点碰撞

我现在的痛点都有啥，

ai的输出太长了，没干什么东西，ai说一大堆，其实感觉根本没那么复杂，ai的语言不够精炼，codex好一点，claude code尤其是。

别的就是目前我这套不支持多session，因为没有worktree，有的时候着急的时候还得是work tree

别的感觉就是让ai用最新的api，必要的时候联网搜索，这个我会手动提示。

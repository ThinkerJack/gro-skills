# gro-skills 使用诊断

> 2026-07-28。数据来自 Claude Code 与 Codex 的本地 session 记录，主观部分来自 [`使用记录.md`](./使用记录.md)。
> 本文只描述现状与根因，方案见 [`迭代方案.md`](./迭代方案.md)。

## 结论

这套 skill 的采用率在快速上升：Codex 侧 session 命中率从 4 月的 10% 升到 7 月的 **75%**，7 月单月 **944 次**调用，13 个 skill 全部在跑。

但作者对**调用量最高的四个**评价最低——因为这 944 次没有一次是他主动敲的。

**病根不是"没人用"，是作者不在决策环里。** 流程在自动跑，他在环外看；加上产出型 skill 的产物 review 不动，控制点失去了控制功能。

## 二、核心矛盾：调用量与主观评价成反比

| skill | 7月调用 | 自评 |
|---|---:|---|
| build-it | **150** | 「其实就是执行计划……好像没有特殊的作用」 |
| find-proof | **128** | 「必要性和作用，不好说」 |
| prove-it | **118** | 「这是啥呢，就是让 AI 给我挑刺的」（认错了对象） |
| fix-bug | **64** | 「基本没用过」「目前没什么作用」 |
| write-brief | 8 | 「基本没用到」（唯一吻合的） |

对照唯二获得正面评价的：`research` 和 `poke-holes`——它们恰好是**在 Claude Code 上由作者主动敲**的那两个。

### 机制

> **对一个 skill 的印象只来自主动敲它的次数。自动触发的，跑了等于没跑。**

`prove-it` 是最干净的例证：Codex 侧 140 次（第二高）全自动，Claude 侧 0 次；于是作者对它毫无印象，反而把 `poke-holes`（Claude 侧 11 次，主动敲）的职能记到了它头上。

## 三、根因

### 1. 控制点失去控制功能——不是没触发，是作者不在环里

自述的核心诉求：「需要控制点去干预 AI 的工作，review AI 的思路，而不是只靠一直和他聊天」。

现状：13 个全为 model-invoked，944 次调用全部自动。流程在跑，作者在环外。

这与 mattpocock 批评 GSD/BMAD 的诊断同构——*they take away your control*，只是这里拿走控制权的是作者自己写的 skill。

### 2. 产物 review 不动，控制点即使触发也无法履职

自述精确定位了两处：

- `make-design` 产物：「很长，细节很多，和人类设计的思路不一样，不是那么简洁清晰只说重点」
- `write-spec` 产物：「这里我基本 review 不动了」

应对方式是**让另一个 AI 去 review**——人读不动就换 AI 读。

四个产出型 skill 的产物都是完整文档级，没有一个是"十几个 bullet 三十秒拍板"的粗粒度关卡。

### 3. 阶段划分来自 SDLC，不来自真实干预需求

八个阶段入口，但自述的真实干预需求只有三处：方向对不对、信息收敛对不对、执行序对不对。多出的五个成为噪音，也是作者记不清哪个干什么、把 `prove-it` 认成 `poke-holes` 的直接原因。

### 4. 内容是抽象契约，而 944 次调用把冗余成本放大了

13 个平均 2 KB，主体是「产出应包含 X、Y、Z」式契约，以及约 50 条「不…」开头的禁令。

7 月 944 次加载意味着**每 1 KB 冗余都被反复付费**，也是「慢」的一个来源。

两个独立来源指出这两种形态有害：

- superpowers 的 A/B 措辞实测：禁令组产生的不良内容多于配方组，且**劣于不给任何指导的对照组**；追加一条 "除非…" 会让有效指令从稳定退化到噪声
- mattpocock：`don't think of an elephant`——禁令点了它的名，反而更可及

对照获得正面评价的两个：`poke-holes` 4777 字符（其余两倍厚）、`research` 有 L1-L4 分档与具体引擎矩阵——都是**可执行深度**而非抽象契约。

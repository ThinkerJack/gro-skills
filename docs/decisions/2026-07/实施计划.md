## 阶段 1：统一同步机制（半天）

### 1.1 定 mirror / adapter 划分

按迭代方案的新架构重划。判据：**这个 skill 需不需要项目落地细节（文档路径、验证命令、技术栈约定）**。

| 模式 | 成员 | 说明 |
|---|---|---|
| **mirror**<br>整目录逐字覆盖 | find-proof、fix-bug、poke-holes、访谈纪律*(新)* | 纯通用纪律，项目无需干预 |
| **adapter**<br>保留项目薄壳 + `template-*.md` | `/sketch`*(新)*、`/spec`*(重写)*、`/plan`、build-it、prove-it、review-it、save-lesson、commit-it | 需要项目落地细节 |
| **移出名单** | write-brief*(降级)*、set-goal*(拆分)*、make-design*(并入 spec)* | — |

### 1.2 移植同步工具

`vlog-app/tool/sync_gro_skills.dart` → `gro-skills/scripts/sync.py`（约 250–300 行）。

原工具零 Dart 生态依赖（仅标准库 + `git hash-object` / `git rev-parse`），逻辑可直接翻译。

**必须保留的四个设计**：

- `--check` 模式 + 非零退出
- `.gro-skills-sync.json` manifest（`sourceRevision` + 每个 skill 的 `sourceBlob`）
- adapter 的 `SKILL.md` 缺失时**报错而非自动生成**（`refusing to invent it`）
- 校验薄壳确实引用了 `common.md` 与每个 `template-*.md`，防止壳与内容脱节

**需要通用化的五处**：

| 原实现 | 改成 |
|---|---|
| `_defaultSource` 硬编码旧路径 | 自适应解析（参照 `resolve_gro.sh` 的 `pwd -P` 反查）或必填参数 |
| `_destination` 仅 `.agents/skills` | 同时产出 `.claude/skills`（或让它软链到 `.agents/skills`，vlog-app 现行做法） |
| `_ensureRepoRoot` 检查 `pubspec.yaml` | 改查 `.agents/` 或配置文件 |
| mirror/adapter 名单写死在源码 | 移到项目根 `.gro-skills.json` |
| `template-` 前缀硬编码 | 保留约定，写进文档 |

**完成判据**：在 vlog-app 上跑 `sync.py --check`，输出与 dart 版一致。

### 1.3 迁移三个软链仓库

`gro-research`、`vlog-backend`、`mien` 从软链改生成式。

adapter 的薄壳**需要人写**（工具拒绝发明），按 vlog-app 的 10 行模板改写：

```markdown
# 本仓 <职能>入口
1. 完整读取 `references/common.md`，执行 Gro Skills 的通用契约。
2. 完整读取 `references/template-<x>.md`，应用本仓<具体内容>。
3. 冲突时以用户最新要求、当前计划和就近 `AGENTS.md` 为准。
```

初次迁移时 `template-*.md` 可以只写一行占位，后续按实际经验补。

### 1.4 废弃软链方案 + 挂 check

- `sync-project-skills.sh` 标记废弃，README 改写
- **`--check` 挂 pre-commit 或 CI**

**1.4 后半条是这个阶段最重要的一步**：vlog-app 的 mirror 已经两周没同步（`poke-holes` 停在 30 行、上游已 80 行），`--check` 本可发现，但没人主动跑。不挂钩子就会重演。

### 1.5 决定文件进不进 git

生成式产出真实文件，**建议提交**——这是相对软链的决定性优势：同事 clone 即用，无需知道 gro-skills 的存在。

同时给 `docs/.gitignore` 加白名单，让四份文档（使用记录/使用诊断/迭代方案/实施计划）进版本控制。

### 3.2 `/spec` 的完成判据

- **厚在纪律**：冲突裁决、时效判定、准入门槛、与仓库现状交叉验证
- **厚在格式**：`SPEC-FORMAT.md` 单独文件承载来源清单骨架
- **人区一屏内**，超了触发拆分
- **人区 / AI 区物理分开**——人只看目标/范围/非目标/关键取舍/验收
- 不出现「产出应包含 X、Y、Z」式抽象契约

### 3.5 no-op 清理的操作方式

逐句问：**这句话相对模型默认行为改变了什么？** 没有就删整句，不修剪用词。

约 50 条「不…」的处理：能正向表述的改正向；**不写"除非…"豁免**；需要条件分支的挂在可观测谓词上；只有权限类硬护栏保留禁令形态。
